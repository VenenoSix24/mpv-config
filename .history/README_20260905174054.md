# mpv-config

mpv-lazy（hooke007/mpv_PlayKit）的配置管理仓库。mpv-lazy 升级时需要全新安装到另一个目录、迁移配置后删除旧目录，所以配置以本仓库为唯一权威版本，安装目录只是部署目标。

## 目录结构

- `config/` — 实际维护的 portable_config 全部内容。
- `docs/` — 修改记录。`CHANGELOG.md` 是总索引，单次较大的改动单独一份 md。
- `upstream/` — 每次安装新版 mpv-lazy 时留存的原版 portable_config 快照，用于升级时对比。
- `sync_from_mpv.bat` — 安装目录 -> 仓库）。
- `sync_to_mpv.bat` — 仓库 -> 安装目录（只覆盖新增/修改，不删除）。

## 日常流程

1. 直接改 `portable_config` 里的文件（改完在 mpv 里重载立即看效果）。
2. 改满意后运行 `sync_from_mpv.bat` 收回仓库。
3. `git status` / `git diff` 检查，`git commit`（中文祈使句，如 `fix: 修正进度条隐藏时机`）。
4. 有必要的话在 `docs/CHANGELOG.md` 补一条记录。

## 升级到新版 mpv-lazy 的流程

1. 在新目录（如 B）全新安装新版 mpv-lazy。
2. 把 B 目录的原版 `portable_config` 整个复制到 `upstream/`，命名如 `v20260905_orig_portable_config`。
3. 运行 `sync_to_mpv.bat`（脚本内 MPV_DIR 先改成 B 目录）把仓库配置部署过去。
4. 对比 `upstream/快照` 和 `config/`：
   - 作者新增/修改的配置项、脚本，diff 快照与上一版快照可知（这就是"不漏掉作者新增内容"的办法）。
   - 自己的改动需要重新套用到作者更新过的文件（尤其 `scripts/uosc` 源码）时，diff 快照与 config 即可看到自己的全部改法。
5. 在 B 目录验证没问题后删除旧安装目录，更新下面的"当前安装目录"。
